# Архитектура ИИ-агента «Элин» в Telegram

Этот документ описывает основные компоненты системы для создания AI-агента Элин, который общается с пользователями в Telegram, опирается на глубокую базу знаний, помнит контекст, имеет доступ в интернет и предоставляет доступ по подписке. Включает мультимодальность и поддержку голосовых сообщений.

## 1. Технический стек

| Компонент | Инструмент / Технология | Описание |
| :--- | :--- | :--- |
| **Интерфейс бота** | Telegram Bot API | Платформа для общения с подписчиками. |
| **Бэкенд (Оркестратор)** | Python 3.12+ (Aiogram 3.x) | Вся асинхронная логика работы бота (обработка входящих, вызов LLM, проверка лимитов, память, Tool Use). Полный контроль над приложением. |
| **LLM (Мозг ИИ, Фото)**| OpenRouter (Claude 3.5 Sonnet / GPT-4o)| Маршрутизация запросов (тексты и анализ фото), обеспечивает максимальную гибкость. |
| **Голос (Распознавание)**| OpenAI Whisper API / Groq | Транскрибация голосовых сообщений пользователей (Голос -> Текст). |
| **Поиск в сети (Web Search)**| Serper API / Tavily | Доступ в интернет для поиска актуальных товаров, цен и трендов в реальном времени. |
| **База данных** | SQLite (aiosqlite/SQLAlchemy) | Хранение профилей, начала триала, фактов о пользователях, статуса подписки (локальный файл). |
| **База знаний (RAG)** | Векторная БД (FAISS/ChromaDB) | Векторная база данных для базы знаний и материалов. |
| **Админ-панель** | Внутри Telegram бота | Команда `/admin` для управления настройками (API ключи, промпты, тарифы, выдача подписок ручным способом). |
| **Оплата**| Telegram Stars, CryptoBot, Boosty | Нативная оплата, автоматическая крипта и ручная обработка чеков с Boosty/Patreon. |

## 2. Разбор и Решения по Ключевым Моментам

### 2.1. Админ-панель и Динамические настройки
Все гибкие параметры бота будут храниться в локальной базе данных **SQLite**. 
Мы реализуем закрытую **Админ-панель прямо внутри Telegram бота** (вызов командой `/admin`, меню доступно только определенному `user_id`).
Через удобные Inline-кнопки администратор сможет:
- **Настройки LLM:** Менять API-ключи и переключать активную модель.
- **Системный Промпт:** Редактировать инструкции Элин напрямую из чата.
- **Денежные настройки:** Указывать цены тарифов (1м, 3м, 1г) в Stars и USDT.
- **Пользователи:** Выдавать подписку нужным профилям по клику без захода в базу.

### 2.2. Формирование Базы Знаний (RAG)
Так как база знаний еще не сформирована, мы реализуем "пустышку" (оставим место для сервиса RAG на будущее). Когда контент Элин (ее посты, статьи, манифест) будет готов, мы напишем отдельный Python-сервис, который загрузит эти тексты в локальную векторную базу данных (например, `FAISS` или `ChromaDB`), где они будут автоматически искаться перед отправкой запроса к LLM.

### 2.3. Монетизация и Система Подписок
Для доступа к боту будет внедрена **модель по подписке (Subscription)**.
**Тарифная сетка:**
- **Free Trial:** 48 часов полностью бесплатного тестирования, отсчет стартует после первого сообщения пользователя.
- Палитра подписок: 1 месяц, 3 месяца, 1 год (со скидками).

**Методы оплаты (встроенный Paywall):**
- **Telegram Stars (Звезды):** Нативная система оплаты в Telegram с Apple/Google Pay.
- **CryptoBot (@CryptoBot):** Автоматическая генерация счетов в криптовалюте (USDT/TON) и обработка вебхуков.
- **Boosty / Patreon / Альтернативные шлюзы:** Кнопка оплаты на сторонней площадке. Пользователь отправляет скриншот или email, бот пересылает его админу, выдача подписки происходит нажатием одной кнопки в админке ("✅ Выдать доступ").

### 2.4. Долгосрочная память (Имя, предпочтения, факты)
Для долгосрочного "удержания" контекста нам нужно, чтобы агент не просто читал последние сообщения. Мы внедрим механизм **Экстракции Фактов (Memory Extraction)**. 
- Во время диалога LLM параллельно анализирует реплики пользователя и вычленяет важную информацию (Имя: Александр, Возраст: 32, Любит: кофе, дизайн, Тема общения: Slow Living).
- Эти факты сохраняются в отдельную JSON колонку (`user_facts`) в таблице пользователей в **SQLite**.
- К каждому текущему запросу Элин будет подкладываться карточка профиля собеседника.

### 2.5. Мультимодальность (Голос и Фото) и Мультиязычность
- **Голос:** Пользователь может отправлять войсы. Бэкенд (через Aiogram) перехватывает аудио, скачивает его, конвертирует в нужный формат и отправляет в **Whisper API** (копеечная стоимость, высочайшая точность). Готовый текст подается AI-агенту. Пока Элин отвечает текстом (позже подключим ElevenLabs для TTS генерации "тихой, эстетичной" озвучки).
- **Фотографии:** При получении фото агент сможет консультировать по гардеробу стилю или интерьеру благодаря функции Vision, встроенной в современные модели LLM.
- **Мультиязычность:** Для Элин будет закреплено жесткое системное правило: «Определяй язык собеседника автоматически и отвечай на том же языке, сохраняя свой фирменный стиль тихого спокойствия».

### 2.6. Выбор Модели в OpenRouter
Мы будем маршрутизировать запросы через платформу **OpenRouter**.
* **Рекомендация: Anthropic Claude 3.5 Sonnet.** Это сейчас лучшая модель на рынке в плане эмпатии, эмоционального интеллекта и живого, естественного языка с глубоким пониманием нюансов. Claude великолепно пишет и блестяще анализирует фото (особенно интерьеры и одежду).
* **Резерв: OpenAI GPT-4o.** Сильная модель, которую можно будет включать по умолчанию как страховку.

### 2.7. Доступ в Интернет (Web Search Capability)
Чтобы Элин могла советовать конкретные вещи (одежду, мебель) и находить актуальные места для покупки, мы интегрируем в наш Python-бекенд инструмент веб-поиска (например, **Serper API** или **Tavily**).
* **Как это работает:** Если пользователь спрашивает «Где купить такую лампу?» или агент хочет дать ссылки, LLM (через механизм Tool Use / Function Calling) возвращает команду вызова поиска. Наше приложение перехватывает команду, делает HTTP-запрос к API поиска в интернете, получает результаты и пробрасывает их обратно в LLM для формирования итогового ответа.
* **Стилизация ответов:** Элин получит системную инструкцию фильтровать результаты и рекомендовать магазины или бренды, соответствующие философии «Quiet Luxury», по возможности избегая дешевого масс-маркета с "визуальным шумом" (если пользователь не ищет базовые вещи целенаправленно).

### 2.8. Примерная себестоимость использования ИИ
В OpenRouter оплата идет за токены (длину текста). 
Если представить интенсивный 1 час общения пользователя с Элин (около ~50-60 сообщений туда и обратно + переданные фото, аудио и поисковые запросы):
- **Текст и Поиск:** Обновление контекста и вызов поиска увеличат потребление. В среднем 250,000 входящих и 18,000 исходящих токенов (используя Claude 3.5 Sonnet) обойдутся в ~$0.75 + ~$0.27.
- **Голос (Whisper):** Транскрипция 30 минут речи будет стоить ~$0.18.
- **Фото:** Осмотр 5-10 фотографий обойдется примерно в ~$0.05.
- **Поисковые запросы API (Tavily/Serper):** Микроскопическая стоимость (около $0.001 за запрос, так что ~$0.01 за сессию).
**Итого:** Около **$1.20 — $1.60** за 1 час невероятно плотного общения. При базовом потреблении (пара вопросов в день) будет выходить до $0.15 в день на активного пользователя.

### 2.9. Добавления от ИИ (Результат архитектурного моделирования)
1. **Агрегация сообщений с фото (Альбомы).** В Telegram отправка нескольких фото (MediaGroup) приходит в систему как серия отдельных сообщений. В Aiogram нужно будет реализовать MediaGroup Middleware или фоновую задачу (asyncio буфер на 2-3 секунды), которая соберет все фото из альбома в один комбинированный запрос к LLM.
2. **Формат Биллинга клиентов / Лимиты.** Поскольку расходы идут за сообщения, а не поминутно, бизнес-модель "сеансов" лучше ограничивать пакетом сообщений (например, "1 консультация = 60 сообщений"). Продавать "время" может быть опасно для экономики.
3. **Vision Промпт в стиле Элин.** Когда ей присылают фото, мы дополнительно инжектим правило: "Анализируй визуальные образы через призму Quiet Luxury. Предлагай убирать визуальный шум, добавлять природные текстуры, спокойные силуэты и приглушенные цвета".

## 3. Модульный План Разработки (Phased Roadmap)

Чтобы не завязнуть в настройках сразу, разработка Элин разбивается на 4 логических этапа (фазы). Мы будем переходить к следующему этапу только после обкатки предыдущего.

### Этап 1: MVP (Базовый Интеллект и Интернет)
* **Цель:** Запустить жизнеспособного умного помощника.
* **Функционал:** 
  - Создание архитектуры Python-приложения (Aiogram 3.x), настройка модульного роутинга в боте.
  - Подключение агента на базе LLM через OpenRouter API (Claude 3.5 Sonnet) с сохранением контекста.
  - Поддержка распознавания фотографий пользователя (Vision).
  - Интеграция механизмов Tool Use.
  - **Поиск в сети (Web Search)** для поиска актуальных вещей в интернет-магазинах.
  - База данных (SQLite): создание таблиц для агрегации памяти, профилей, хранения настроек и сроков подписок.

### Этап 2: Эмпатия, Голос и Понимание (Soft Skills)
* **Цель:** Сделать общение живым и контекстным.
* **Функционал:**
  - Подключение **Whisper API** (пользователь может отправлять голосовые).
  - Настройка **Weather API** для атмосферных и заботливых завязок диалога.
  - Интеграция **Link/Web Reader**: возможность кинуть ссылку на магазин/статью, чтобы Элин дала оценку.
  - Продвинутая экстакция фактов в долгосрочную память.

### Этап 3: Цифровая Муза и Монетизация
* **Цель:** Визуальный вау-эффект и запуск бизнес-модели.
* **Функционал:**
  - **Генерация референсов (Image Generation)**: создание эстетичных мудбордов и образов в ответ на запросы.
  - **Голос Элин (TTS)**: Подключение ElevenLabs, чтобы Элин могла отправлять собственные спокойные голосовые сообщения.
  - Интеграция биллинга: Telegram Payments для подписок.
  - Запуск админ-панели настроек.

### Этап 4: Экосистема и Глубокая интеграция
* **Цель:** Сделать Элин постоянным спутником пользователя.
* **Функционал:**
  - База знаний (RAG) со стилистическим Манифестом и статьями Элин.
  - **Интеграция с Notion** (Mindful Planning): возможность собирать покупки или трекать настроение прямо в эстетичный Notion-дашборд пользователя.
